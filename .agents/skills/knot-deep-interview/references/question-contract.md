# 인터뷰 질문 계약

## 시작 전 근거 판정

다음 항목마다 확인 내용과 출처가 명시됐는지 먼저 확인한다.

1. 현재 맥락
2. 구체적인 문제 상황
3. 선택 필요성
4. 실제로 검토한 대안
5. 최종 선택
6. 선택 이유

사용자가 인터뷰를 명시적으로 요청하지 않았고 여섯 항목이 모두 명시돼 있으며 자료 간
충돌이 없고 현재도 유효하면 질문을 시작하지 않는다. 항목별 내용과 출처를
`interview.evidence`에 기록하고 `status=skipped`로 반환한다. 하나라도 누락됐거나
충돌·현재 유효성 불명확 상태면 해당 판단부터 질문한다.

다음 순서를 체크리스트가 아니라 우선순위로 사용한다. 가장 불명확하고 실행 결과를 크게
바꾸는 항목을 한 번에 하나씩 질문한다. 대안이 없었으면 `없음`이라고 답해도 된다고
명시한다.

1. 어떤 맥락에서 논의가 시작됐는가
2. 누가, 언제, 무엇을 겪었는가
3. 왜 지금 선택이 필요한가
4. 회의나 대화에서 실제로 검토한 선택지는 무엇인가
5. 어떤 선택을 했으며 왜 선택했는가
6. 그 선택으로 감수하는 단점은 무엇인가
7. 어떤 조건에서 다시 논의할 것인가
8. 원하는 결과와 관찰 가능한 변화
9. 포함 범위와 비목표
10. 정상·실패·취소·재시도·복구 흐름
11. 기존 데이터·API·사용자 흐름과 바뀌는 계약
12. 성공·실패 기준과 실패 후 행동
13. AI가 정할 구현 세부와 사람이 정할 제품 정책

사용자가 대안이 없었다고 답하면 현상 유지 또는 선택한 안의 반대 방향도 실제로 검토하지
않았는지 한 번만 확인한다. 그래도 없으면 `alternatives_confirmed=false`로 기록하고 ADR을
만들지 않는다. AI가 떠올린 대안은 참고 제안일 뿐, 팀이 검토한 대안으로 기록하지 않는다.

최소 한 라운드는 앞선 답변의 구체적 사례, 숨은 가정 또는 포기할 트레이드오프를 다시
묻는다. 저장소에서 확인할 수 있는 사실은 질문 대신 근거로 기록한다.
