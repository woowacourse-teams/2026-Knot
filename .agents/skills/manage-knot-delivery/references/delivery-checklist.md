# Delivery 실행 체크리스트

## Issue

1. 문제, 기대 결과, 포함·제외 범위, 완료 조건을 확인한다.
2. 제목 영역과 영역 Label이 일치하는지 확인한다.
3. 유형 Label은 하나만 선택한다.
4. 작업자 Label과 Assignee를 양방향으로 대조한다.
5. 의존성, 명세 확인일, ADR 상태, 검증 방법을 확인한다.
6. Ready 조건을 만족할 때만 `Ready`로 이동한다.

## Pull Request

1. 하나의 Issue 결과만 포함하는지 확인한다.
2. `Closes #번호`가 실제 대상 Issue를 가리키는지 확인한다.
3. Issue와 PR의 영역·유형·작업자 메타데이터를 일치시킨다.
4. 모든 필수 본문 섹션에 실제 내용을 작성한다.
5. 영향 없음이나 ADR 불필요도 이유와 함께 명시한다.
6. 실행한 검증 명령과 결과를 기록한다.
7. CI, 리뷰, 미해결 대화를 확인한 뒤 병합 조건을 판정한다.

## 보고

- 변경한 GitHub 객체와 메타데이터를 요약한다.
- 자동 검증 결과를 성공 또는 실패 항목별로 알린다.
- 권한 부족, 미확정 정책, 누락 매핑은 추측하지 않고 차단 사유로 남긴다.
