# 워크스페이스 초대는 복수 발급과 수단별 시간 만료만 제공한다

## 상태

Proposed

## 관련 Issue

- #399 [BE] 워크스페이스 초대를 취소 없는 복수 발급으로 전환
- #440 [BE] 초대 수단별 만료 저장 구조 추가

## 한 줄 요약

워크스페이스 초대는 코드와 링크를 함께 발급하되 각각의 만료 시각으로 판단하고, 수동 취소 없이 시간이 지나야 만료된다.

## 왜 이 결정이 필요했나

기존 ADR 171은 하나의 초대가 코드와 링크를 공유 만료로 관리하고 재발급 때 기존 초대를 무효화한다고 정했다. 이후 제품 요구가 바뀌어 여러 초대와 여러 멤버의 수락을 허용해야 한다. 사용자는 2026-10-03에 초대 취소 기능을 MVP에서 제외하고, 링크는 시간이 지나야만 만료되도록 확정했다.

## 무엇을 결정했나

- 새 발급은 기존 초대를 무효화하지 않는다.
- 코드와 링크는 각각 만료 시각을 가진다.
- 기본 TTL은 두 수단 모두 24시간이다.
- 수동 취소, 연장, 복원, 사용 횟수 제한은 MVP에서 제공하지 않는다.
- 이미 invalidated_at이 기록된 과거 초대는 새 판단에서도 계속 무효다.
- Workspace가 삭제되면 만료 전 초대라도 preview와 accept에서 거절한다.
- 코드와 링크 원문은 새 발급 응답에서만 제공하고 상태 목록이나 후속 조회에서 재표시하지 않는다.

## 유지하는 보안 결정

ADR 229의 keyed hash와 AES-GCM 암호문 저장은 유지한다. 참여와 미리보기 조회는 원문 대신 keyed hash로 찾고, 원문 재노출이 필요한 범위는 신규 발급 응답으로 좁힌다.

## 결과

- Workspace마다 여러 유효 초대가 존재할 수 있다.
- 한 초대의 코드가 만료돼도 링크가 남아 있으면 링크 경로는 계속 사용할 수 있다.
- 잘못 공유한 초대를 개별 차단하는 기능은 없다.
- 기존 숫자 포함 코드는 서버가 기존 만료까지 호환한다.
- 구 단일 조회와 재발급 API는 소비자 전환 뒤 별도 이슈에서 제거한다.

## 다시 논의해야 할 조건

- 유출된 초대를 만료 전 차단해야 한다.
- 발급자별 감사나 OWNER 전용 취소가 필요하다.
- 초대 사용 횟수 제한이나 일회용 초대가 필요하다.
- 키 관리 방식이나 원문 재표시 요구가 달라진다.
