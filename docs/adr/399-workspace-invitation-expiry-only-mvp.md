# 한 초대에 코드와 링크를 발급하고 각각 시간으로만 만료한다. 복수 초대·다수 수락을 허용하며 취소·발급자 관리를 제외한다.

## 상태

Proposed

## 관련 Issue

- #399 [BE] 취소 없는 복수 초대와 수단별 만료

## 한 줄 요약

한 초대에 코드와 링크를 발급하고 각각 시간으로만 만료한다. 복수 초대·다수 수락을 허용하며 취소·발급자 관리를 제외한다.

## 왜 이 결정이 필요했나

기존 초대는 공통 24시간 만료와 재발급 무효화를 사용한다. 사용자는 최소 MVP 단순화와 작은 PR 단위를 요청했다.

발급자별 취소와 목록을 도입하면 기존 행의 미확인 발급자 이관과 추가 API가 필요했다. 사용자에게 필요한 코드 입력·링크 공유·다수 수락은 유지해야 한다.

결정 동인:

- 사용자가 확정한 입력·공유 규칙 보존
- MVP 관리 기능 최소화
- 기존 유효·만료·무효 초대 효력 보존

## 트레이드 오프

- 단일 재발급: 관리가 단순하지만 복수 유효 초대 요구와 충돌해 미채택
- 발급자 또는 OWNER 취소: 만료 전 차단이 가능하지만 권한·관리 흐름이 늘어 미채택
- 취소 없는 복수 초대: 다수 공유를 유지하고 관리 기능을 줄이지만 만료 전 개별 차단 불가; 채택

## 무엇을 결정했나

한 초대에 코드와 링크를 발급하고 각각 시간으로만 만료한다. 복수 초대·다수 수락을 허용하며 취소·발급자 관리를 제외한다.

사용자는 최소 MVP를 수용한 뒤 취소 기능만 제외했다. 코드·링크 독립 만료와 복수 수락은 유지한다.

## 결과

- 신규 코드는 A-Z 6자리, 코드·링크 각각 기본24시간 서버 TTL이며 사용자 지정·연장·복원은 없다
- 비삭제 Workspace 활성 OWNER/MEMBER가 발급하며 원문은 발급 응답에서만 제공한다. OWNER 목록은 원문 없이 상태만 제공한다
- legacy expires_at과 invalidated_at의 효력을 보존하고 발급자를 추측하지 않는다
- I01은 저장 기반만 확장한다. 기존 단수 UNIQUE·고정24시간 호환 컬럼·구 API는 후속 전환까지 유지한다
- 복수 발급 공개 전에 구 재발급·원문 조회를 차단하고 숫자 코드의 FE 사용 경로 또는 자연 만료를 확인한다
- Superseded 범위: ADR171의 공통 만료·단일 초대·재발급 무효화 정책. ADR229의 HMAC·난수·비밀값 보호는 유지하며 암호문 재조회 제거는 후속 #404다
- Workspace 삭제는 별도 접근 차단이다. 만료 전 개별 취소가 없는 위험을 수용한다

## 다시 논의해야 할 조건

- 실제 유출 대응으로 개별 취소가 필요할 때
- 사용 횟수 제한이나 사용자별 TTL이 필요할 때
