# Workspace 삭제는 논리 삭제로 처리하고 진행 중·일시정지 녹음은 저장 없이 폐기하며 기존 저장 파일은 보존한다

## 상태

Proposed

## 관련 Issue

- #410 [BE] 워크스페이스 삭제 API와 진행 중 녹음 폐기 적용

## 한 줄 요약

Workspace 삭제는 논리 삭제로 처리하고 진행 중·일시정지 녹음은 저장 없이 폐기하며 기존 저장 파일은 보존한다

## 왜 이 결정이 필요했나

V2 MVP에서 OWNER는 권한을 승계하거나 Workspace를 논리 삭제하고 나갈 수 있다. 녹음은 Workspace 안에서 여러 멤버가 동시에 진행할 수 있다.

OWNER가 삭제를 요청한 순간 다른 멤버가 녹음 중이거나 일시정지 상태일 수 있다. 삭제를 막거나 녹음 저장을 기다리면 삭제가 다른 멤버의 녹음에 묶인다.

결정 동인:

- 삭제 요청이 다른 멤버의 녹음에 묶이지 않을 것
- 이미 저장된 오디오·전사·문서는 잃지 않을 것
- 삭제 이후 늦은 요청으로 녹음이 저장·재활성화되지 않을 것

## 트레이드 오프

- 녹음 중이면 삭제 거절: 데이터 손실은 없지만 OWNER가 다른 멤버의 녹음 종료를 기다려야 한다
- 녹음 저장 후 삭제: 녹음을 살리지만 업로드·처리 완료를 기다리는 동안 삭제가 지연되고 실패 처리가 복잡하다
- 저장 없이 폐기 후 즉시 삭제(채택): 삭제가 즉시 끝나지만 진행 중이던 녹음 내용은 잃는다

## 무엇을 결정했나

Workspace 삭제는 논리 삭제로 처리하고 진행 중·일시정지 녹음은 저장 없이 폐기하며 기존 저장 파일은 보존한다

사용자가 원하지 않는 녹음을 보존하려고 삭제를 기다리게 하는 UX를 피한다. 진행 중 녹음만 폐기하고 이미 저장된 자료는 보존해 손실 범위를 제한한다.

## 결과

- 삭제는 한 transaction에서 즉시 끝난다
- 진행 중·일시정지 녹음 내용은 저장되지 않는다
- FE는 삭제 확인에서 폐기 사실을 안내해야 한다
- 폐기 알림과 임시 오디오 정리는 별도 후속 작업이 필요하다

## 다시 논의해야 할 조건

- 진행 중 녹음 보존 요구가 생길 때
- soft delete 복구 요구가 생길 때
