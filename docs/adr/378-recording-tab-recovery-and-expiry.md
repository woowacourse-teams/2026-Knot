# 최초 탭은 새로고침 시 제어를 복구하고 다른 탭은 조회·종료만 허용하며 무응답은 2분 뒤 종료한다

## 상태

Proposed

## 관련 Issue

- #378 [BE] 녹음 시작 API 구현

## 한 줄 요약

최초 탭은 새로고침 시 제어를 복구하고 다른 탭은 조회·종료만 허용하며 무응답은 2분 뒤 종료한다

## 왜 이 결정이 필요했나

최초 탭만 녹음을 제어하며 Member당 활성 세션은 Workspace와 무관하게 하나다

브라우저 이탈 신호는 전달과 닫기·새로고침 구분을 보장하지 않는다

결정 동인:

- 같은 탭의 새로고침은 같은 세션을 자동 복구해야 한다
- 다른 탭·기기 제어 인계 방지
- 브라우저 이탈 신호 유실 허용

## 트레이드 오프

- 이전 안: 새로고침·닫기 모두 종료. 이탈 처리가 단순하지만 새로고침 자동 복구 요구를 충족하지 못한다
- 채택안: 같은 탭 새로고침 자동 복구, 닫기 감지 실패는 2분 무응답 만료. 수집 공백과 닫기 종료 지연을 감수한다

## 무엇을 결정했나

최초 탭은 새로고침 시 제어를 복구하고 다른 탭은 조회·종료만 허용하며 무응답은 2분 뒤 종료한다

기존 녹음 담당자 인터뷰의 자동 복구 요구를 따른다. 최초 탭 증명을 유지하고 종료된 세션은 재활성화하지 않는다

### 최초 탭의 제어 증명

`tabId`는 클라이언트가 보내는 식별값이며 비밀값으로 취급하지 않는다.
같은 회원으로 인증된 다른 탭도 이 값을 바꿔 보낼 수 있으므로, 탭 ID의 일치만으로 제어권을 판단하지 않는다.
최초 탭이 보관한 별도의 비밀값인 `controlToken`을 함께 확인한다.

클라이언트는 암호학적 난수 32바이트로 토큰을 생성하고 같은 시작 요청의 재시도와 같은 탭의 새로고침에서 유지한다.
서버는 회원 인증과 Workspace 소속 검증을 먼저 수행한 뒤, 등록된 탭 ID와 토큰의 증명이 일치하는지 확인한다.
`controlToken`은 로그인 인증이나 Workspace 접근 권한을 대신하지 않는다.

### 해시 저장과 증명의 한계

서버는 토큰 원문 대신 SHA-256 해시인 `controlTokenHash`를 저장한다.
제어 증명은 원문을 복원할 필요 없이 일치 여부만 확인하면 되므로, DB에 원문을 보관할 이유가 없다.
요청으로 받은 토큰을 같은 방식으로 해시해 저장값과 비교하며, 원문과 해시는 일반 응답이나 로그에 노출하지 않는다.

이 방식은 실제 브라우저 탭의 신원을 증명하지 않는다.
같은 회원의 인증 정보와 요청 키·탭 ID·토큰을 다른 탭이나 Postman에 복사하면 서버는 최초 탭과 구분할 수 없다.
FE는 다른 탭·기기에 증명을 공유하지 않아야 하며, 탭 복제 시 저장소 복사와 중복 제어 방지는 #384의 통합 검증 대상이다.

이 PR의 구현은 해시 보관과 시작 증명 비교까지다.
해시 생성은 [PR #423](https://github.com/woowacourse-teams/2026-Knot/pull/423),
토큰 형식·전달 계약은 [PR #424](https://github.com/woowacourse-teams/2026-Knot/pull/424)의 시작 API 문서에 있다.
일시정지·재개·복구 API와 FE 연동은 후속 범위이며, 다른 탭의 조회·종료 허용 정책은 유지한다.

## 결과

- 녹음 상태는 새로고침 전 RECORDING 또는 PAUSED를 유지한다
- 최초 탭이 요청 키·탭 식별자·제어 증명을 유지해야 한다
- 오디오 수집 공백과 닫기 종료 지연을 허용한다
- 종료·복구·만료 HTTP 및 FE 연동은 후속 Issue에서 완성한다
