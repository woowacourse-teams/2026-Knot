# Context Handoff

작업이 중단되거나 담당자가 바뀔 때 다음 사람이 구두 설명 없이 재개할 수 있도록 현재 맥락을 Issue 또는 PR에 남깁니다.

## 작성 시점

- 담당자가 변경됩니다.
- 하루 이상 작업을 중단할 예정입니다.
- Issue가 `Blocked`로 이동합니다.
- Draft PR을 다른 사람이 이어서 작업합니다.
- 실패 원인이나 다음 단계가 코드만으로 드러나지 않습니다.

## 작성 위치

1. 열린 PR이 있으면 PR 설명 또는 최신 댓글에 기록합니다.
2. PR이 없으면 Issue 댓글에 기록합니다.
3. 두 위치에 중복 작성하지 말고 다른 위치에서는 원문 링크만 남깁니다.

## 양식

```markdown
## Context Handoff

- Issue: #번호
- 현재 상태: In Progress | In Review | Blocked
- 목표: 이번 작업이 완료해야 하는 결과

### 완료한 내용

- 구현하거나 확인한 내용

### 현재 작업 상태

- 수정한 주요 파일과 아직 끝나지 않은 부분
- 마지막으로 확인한 commit 또는 branch

### 검증 결과

- 실행한 명령
- 성공/실패 결과와 핵심 오류

### 결정과 참고자료

- 관련 Notion 명세, ADR, API 문서 링크
- 이미 검토했고 제외한 대안

### 차단 사항

- 차단 원인
- 해제 조건
- 확인 담당자 또는 외부 의존성

### 다음 단계

1. 다음 담당자가 가장 먼저 할 일
2. 이어서 수행할 검증

### 주의사항

- 비밀값, 로컬 전용 설정, 되돌리면 안 되는 변경
```

## 품질 기준

인계 기록만 읽은 다음 담당자가 아래 질문에 답할 수 있어야 합니다.

- 무엇을 왜 만들고 있습니까?
- 어디까지 완료됐습니까?
- 어떤 파일을 보고 어떤 명령을 실행해야 합니까?
- 무엇이 실패하거나 차단되어 있습니까?
- 이미 내린 결정과 다시 논의해야 할 결정은 무엇입니까?
- 가장 안전한 다음 행동은 무엇입니까?

토큰, 비밀번호, 개인 정보는 인계문에 기록하지 않습니다. 필요한 비밀값은 팀이 정한 별도 비밀 관리 경로만 안내합니다.
