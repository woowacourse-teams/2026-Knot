# Definition of Ready / Done

Ready와 Done은 작업량이 아니라 작업 가능 여부와 완료 여부를 같은 기준으로 판정하기 위한 팀 계약입니다.

## Definition of Ready

아래 필수 항목을 모두 만족한 Issue만 `Ready`로 이동합니다.

- [ ] 해결하려는 문제와 기대 결과가 설명되어 있습니다.
- [ ] 구현 범위와 제외 범위가 구분되어 있습니다.
- [ ] 확인 가능한 완료 조건이 체크리스트로 작성되어 있습니다.
- [ ] 선행 Issue와 외부 의존성이 해결됐거나 명확히 연결되어 있습니다.
- [ ] 필요한 Notion 기획·명세 링크와 마지막 확인일이 있습니다.
- [ ] API, DB, Notion 연동에 미치는 영향이 식별되어 있습니다.
- [ ] ADR 필요 여부가 `필요`, `불필요`, `검토 중` 중 하나로 표시되어 있습니다.
- [ ] 검증 방법이 단위·통합·인수·수동 확인 중 적절한 수준으로 제시되어 있습니다.
- [ ] 한 명이 주도할 수 있고 하나의 PR을 기본 단위로 삼을 수 있는 크기입니다.

다음 상황에서는 `Ready`로 이동하지 않습니다.

- 제품 정책이나 API 동작을 추측해야 합니다.
- 접근 권한, 인증 정보 또는 테스트 데이터가 없어 검증할 수 없습니다.
- 열린 선행 Issue의 결과에 따라 구현 방향이 달라집니다.
- 완료 조건이 “기능 구현”처럼 결과를 판정할 수 없는 표현뿐입니다.

## Definition of Done

아래 항목 중 변경과 관련된 조건을 모두 만족해야 `Done`으로 판단합니다.

### 기능과 품질

- [ ] Issue의 완료 조건을 모두 충족합니다.
- [ ] 정상 흐름과 주요 실패 흐름이 검증되었습니다.
- [ ] 관련 단위·통합·인수 테스트가 통과합니다.
- [ ] 임시 코드, 디버그 출력, 불필요한 주석이 제거되었습니다.

### 계약과 문서

- [ ] API 변경이 Swagger UI / OpenAPI에 반영되었습니다.
- [ ] DB 변경에 재현 가능한 migration 또는 DDL과 검증 방법이 있습니다.
- [ ] 중요한 기술 결정이 관련 ADR에 기록되었습니다.
- [ ] 사용자 또는 팀원의 사용 방법이 달라지면 관련 문서를 갱신했습니다.

### 협업과 배포 준비

- [ ] PR이 관련 Issue를 `Closes #...`로 연결합니다.
- [ ] PR 본문에 변경 이유, 영향 범위, 검증 결과가 있습니다.
- [ ] CI와 필수 리뷰가 통과했습니다.
- [ ] 모든 리뷰 대화가 해결되거나 합의된 후속 Issue로 분리되었습니다.
- [ ] PR이 `main`에 병합됐습니다.
- [ ] Issue와 Project 상태가 `Done`으로 정리됐습니다.

## 예외 처리

- 외부 장애로 검증 일부를 수행할 수 없으면 완료로 숨기지 않고 Issue를 `Blocked`로 둡니다.
- 범위 밖 개선은 현재 Issue의 완료를 막지 않도록 별도 Issue로 분리합니다.
- 완료 조건 자체가 잘못됐다는 사실을 발견하면 PR에서 임의로 바꾸지 않고 Issue에서 변경 이유를 합의합니다.
