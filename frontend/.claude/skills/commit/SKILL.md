# commit 작성 커맨드

이 커맨드는 현재 워킹 디렉토리의 변경사항을 파악하여 커밋 메시지를 제안하고, 사용자 확인 후 커밋 및 푸시를 수행함.

## 이 커맨드가 하는 일

1. **변경사항 확인** - 코드의 변경사항을 명확히 확인

- `git status` 명령어로 변경된 파일 목록 확인
- `git diff` 명령어로 unstaged 변경사항 확인
- `git diff --staged` 명령어로 이미 staged된 변경사항 확인
- `git log -n 5 --oneline` 명령어로 최근 커밋 메시지 스타일(컨벤션) 파악

2. **커밋 대상 및 커밋 메시지 제안** - 확인된 변경사항을 바탕으로 커밋 메시지 초안 작성

- 어떤 파일을 `git add`할지 목록으로 정리하여 제시
  - 변경사항은 최대한 작게 나누어 커밋
- 변경사항에 맞는 커밋 메시지를 아래 형식에 맞춰 작성
- **[매우 중요]** 제안 내용을 사용자에게 출력한 후 반드시 승인을 요청하고 **대기**. 승인 없이는 절대로 add, commit, push 수행 금지.

3. **커밋 및 푸시 수행** - 사용자가 승인한 경우에만 실행

- 사용자가 "네", "좋아요", "진행해주세요", "ok", "ㄱㄱㄱ" 등 긍정적인 응답을 한 경우에만 다음 단계 진행.
- 제안한 파일들을 `git add`.
- 승인된 커밋 메시지로 `git commit -m "<메시지>"` 실행.
  - **[매우 중요]** 커밋 메시지에 `Co-Authored-By` 트레일러나 Claude/생성 도구 관련 서명을 **절대 추가하지 않음.** 승인된 메시지 본문만 그대로 사용.
- `git branch --show-current` 명령어로 현재 브랜치 확인.
- `git push origin <현재 브랜치>` 명령어로 현재 브랜치에 푸시.
- 사용자가 메시지 수정을 요청한 경우, 수정사항을 반영하여 **다시 승인을 받는 과정**을 반복.

## 작동 방식

- 변경사항을 명확하고 정확하게 파악.
  - `git status` 명령어로 변경 파일 목록 확인
  - `git diff` 및 `git diff --staged` 명령어로 실제 코드 변경사항 확인
  - `git log -n 5 --oneline` 명령어로 기존 커밋 컨벤션 확인

- 확인된 변경사항을 기반으로 커밋 대상 파일과 커밋 메시지를 제안. (최대한 작게 나누어 커밋)
  - 기존 커밋 로그의 스타일(예: Conventional Commits, gitmoji 등)을 우선적으로 따름.
  - 변경사항이 서로 다른 맥락을 포함하는 경우 사용자에게 커밋 분리 여부를 질문.

- 사용자의 승인을 받은 후에만 실제 git 명령어 실행.
  - 승인 전에는 **절대로** `git add`, `git commit`, `git push` 실행 금지.

## 커밋 메시지 형식

기존 커밋 로그의 컨벤션을 우선적으로 따르되, 확인되는 컨벤션이 없는 경우 아래의 Conventional Commits 형식을 기본값으로 사용.

```
<type>: <제목>

<본문 - 필요시에만 작성>

<트레일러 - #issue번호>
```

- **type**: `feat`, `fix`, `refactor`, `style`, `docs`, `setting`, `chore` 중 적절한 것을 선택
- **제목**: 50자 이내, 명령형 어조, 한글로 작성
- **본문**: 변경 이유 및 맥락이 필요한 경우에만 작성, 각 줄은 72자 이내

## 사용자 확인 요청 형식

커밋 수행 전, 아래 형식으로 사용자에게 확인을 요청.

```
## 커밋 대상 파일

- path/to/file1.js
- path/to/file2.js

## 제안 커밋 메시지

feat: 프로필 사진 업로드 기능 추가

S3 presigned URL을 통한 프로필 사진 업로드 기능을 구현하였습니다.

## 푸시 대상 브랜치

feature/profile-upload

---

위 내용으로 커밋 및 푸시를 진행할까요? 수정이 필요하시면 말씀해주세요.
```

## 커밋 메시지 작성 예시

```
feat: 프로필 사진 업로드 및 제거 기능 구현

S3 presigned URL 방식으로 프로필 사진 업로드 플로우를 구현하였습니다.
GestureDetector를 활용하여 업로드할 이미지의 크기 및 위치 조정이 가능하도록 하였습니다.

#12
```

```
fix: 로그인 후 리다이렉트 경로 오류 수정

소셜 로그인 이후 의도하지 않은 경로로 이동하던 문제를 수정하였습니다.

#1
```

## 주의사항

- **[매우 중요]** 사용자의 **명시적 승인 없이는 절대로** `git add`, `git commit`, `git push` 실행 금지.
- **[매우 중요]** 해당 스킬은 절대로 코드를 작성하거나 수정하지 않음. 오직 git 관련 동작만 수행.
- **[매우 중요]** 커밋 메시지에 `Co-Authored-By:` 트레일러를 포함한 어떠한 공동 작성자(co-author) 서명이나 Claude/생성 도구 관련 문구도 추가 금지. 하네스 기본값으로 co-author가 붙도록 설정되어 있더라도, 이 스킬에서는 해당 트레일러를 제외하고 커밋. 이슈 번호의 경우에는 트레일러에 무조건 포함.
- 이미 staged된 파일이 있다면, 해당 내역을 사용자에게 먼저 보여주고 그대로 포함할지 질문.
- 현재 브랜치가 `main`, `master`, `develop`, `dev` 등 보호 브랜치로 추정되는 경우, 푸시 전에 **반드시** 사용자에게 재확인.
- 원격 브랜치가 아직 없는 경우 `git push -u origin <현재 브랜치>` 형태로 upstream을 설정하며 푸시.
- push 과정에서 충돌이나 rejected 오류가 발생한 경우, 임의로 `--force` 옵션을 사용하지 않고 사용자에게 상황을 보고한 뒤 지시를 대기.
