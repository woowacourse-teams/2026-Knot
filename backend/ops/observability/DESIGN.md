# Knot 관측 대시보드 화면 계약

## 1. 화면 정체성

Grafana의 기존 기본 컴포넌트를 유지한다. 사용자가 먼저 환경을 선택하고 상태 → 로그 → 서버 → 런타임/DB로 이동한다. 새 앱이나 CSS를 만들지 않는다.

## 2. 색상

Grafana 테마의 배경·패널·텍스트·링크 토큰을 사용한다. 시계열은 Grafana 기본 팔레트이고 정상 여부를 나타내는 색이 아니다. 상태 Stat은 기존 정상/오류 매핑을 유지하며 색과 함께 텍스트를 표시한다.

## 3. 글자

글꼴·크기는 Grafana 기본값을 사용한다. 화면 제목에 DEV 또는 PROD를 명시한다. 패널 제목은 짧은 한국어로 쓰고, 상세 의미와 다음 확인 위치는 description에 둔다.

## 4. 배치

기존 24칸 gridPos 계약을 사용한다. 안내는 전체 폭, 상태는 12칸씩 두 열, 사용률 Gauge는 8칸씩 세 열, 상태 이력과 로그는 전체 폭이다. 최초 안내 높이는 3칸, 상태 패널은 5칸, Gauge는 6칸, 로그는 10칸이다. 상세 화면은 기존 패널 높이를 유지한다. 스크롤과 좁은 화면의 패널 재배치는 Grafana가 담당한다.

## 5. 재사용 컴포넌트

- 안내 Text: 환경·읽는 순서·데이터 없음 의미를 짧게 표시한다.
- 상태 Stat: 최신 health와 최근 2분 지표 존재를 구분한다. 비어 있으면 정상으로 대체하지 않는다.
- 사용률 Gauge: CPU·메모리·디스크의 최신 사용률을 0~100% 범위로 표시한다. 주의 색은 알림 지속 시간 충족을 뜻하지 않는다.
- 상태 State timeline: health 검사 이력만 표시한다. 배포나 서버 전원 이력으로 해석하지 않고 빈 구간을 연결하지 않는다.
- 시계열: 기존 실제 쿼리와 단위를 유지한다. 요청이 없는 지연·비율은 만들지 않는다.
- 오류 Table: 선택 기간의 URI·HTTP 상태별 오류 건수를 비교한다. 최근 5분 비율과 구분한다.
- 분포 Heatmap: Dev Spring의 실제 histogram bucket만 사용한다. Prod에는 존재하지 않는 지표를 표시하지 않는다.
- 로그: 앱, Nginx, Nginx 5xx를 별도 패널로 표시한다. 타임스탬프·레이블·줄바꿈을 유지한다.
- 탐색 링크: 같은 환경의 화면과 반대 환경의 전체 상태를 구분한다. 시간만 전달하고 변수는 전달하지 않는다.

로딩·오류·키보드 포커스·빈 로그 상태는 Grafana 기본 컴포넌트에 맡긴다. 환경은 선택 변수가 아니라 쿼리의 고정 조건이다.

## 6. 동작

새 애니메이션이나 개발 도구를 설치하지 않는다. 30초 새로고침과 시간 범위 선택을 유지한다. 로그 화면 기본 범위는 1시간이다. 다른 환경 링크를 눌러도 기존 URL 변수로 조회 환경을 바꿀 수 없게 한다.

## 7. 표면

Grafana 기본 패널 배경·테두리·모서리를 그대로 사용한다. 별도 그림·목업으로 실제 조회 화면을 대체하지 않는다. 기존 공통 화면은 호환용으로 보존한다.

## 8. 접근성 제약과 검증 제한

환경을 색만으로 구분하지 않으며 제목과 링크에 명시한다. 로그는 wrapLogMessage를 사용한다. 요청이 적어 로그가 없는 것과 수집기 장애를 동일시하지 않는다. Prod RDS가 프로토타입의 실제 Docker DB가 아님을 표시한다.

실제 Grafana 접근은 저장된 차단 설정으로 제한된다. 375/768/1280px 렌더링, 키보드 동작, 한국어 줄바꿈, 실제 쿼리 응답은 아직 검증하지 않았다. 정적 배치 검증을 시각 QA 통과로 주장하지 않는다. 독립 QA 에이전트는 사용자의 금지 지침을 따른다.

## 9. Discord 알림

한국어 제목에서 환경과 문제를 먼저 식별한다. 본문은 감지 조건, 확인 순서, KST 시각과 링크만 표시한다. 수식의 A/B 값, 전체 라벨과 긴 Silence URL은 표시하지 않는다. 동일 그룹 상세는 최대 2건이며 나머지는 전체 알림 목록 링크로 안내한다. 해제는 규칙 변경으로도 발생하므로 서비스 복구를 확정하지 않는다. Webhook, 라우팅, 평가 쿼리와 임계값은 유지한다.
